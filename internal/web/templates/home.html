How InsomniaXXX Works

No-JS Mode (Tor Safest / Standard HTML): onionguard guards the gateway entrance, while the server encrypts and shards files across decentralized Blossom relays without running any client-side JavaScript:

  • onionguard: Ingress Proof-of-Work admission checkpoint and adaptive DDoS rate limiter defending gateways and Tor hidden services without CAPTCHA tracking.
  • badcrypt: Authenticated encryption (ChaCha20-Poly1305 AEAD). The server encrypts files server-side with a unique 256-bit key embedded in the share link (/d/<hash>/<key>).
  • badrlnc: Random Linear Network Coding (RLNC) over GF(28). Encrypted payloads are partitioned into innovative erasure-coded shards distributed across surviving relays.
  • fiatjaf/nostr: Real-time decentralized Blossom relay discovery via Nostr BUD-04 (kind 10063) network events.
  • go-qrcode: Self-contained offline QR code generation for peer-to-peer mobile transfer with zero external tracking.

Zero-Knowledge Mode (WebAssembly Active): onionguard defends ingress endpoints, while cryptographic keys, AEAD encryption, and RLNC coding run 100% locally inside your browser via WebAssembly:

  • onionguard: Ingress Proof-of-Work admission checkpoint and adaptive DDoS rate limiter defending gateways and Tor hidden services without CAPTCHA tracking.
  • badcrypt: Authenticated streaming encryption (ChaCha20-Poly1305 AEAD) running client-side. The 256-bit encryption key remains strictly in the browser's URL fragment (#key) and is never transmitted over the wire.
  • badrlnc: Random Linear Network Coding (RLNC) over GF(28) running in WebAssembly. Shards are computed locally in-browser and decoded via Gauss-Jordan elimination upon download.
  • fiatjaf/nostr: Real-time decentralized Blossom relay discovery via Nostr BUD-04 (kind 10063) network events.
  • go-qrcode: Self-contained offline QR code generation for peer-to-peer mobile transfer with zero external tracking.
